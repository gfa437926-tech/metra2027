# عقد API ومقترح مخطط سجل الظواهر الجوية

## الحالة

هذه وثيقة تصميم ومراجعة فقط. لم يتم إنشاء جدول أو تنفيذ migration أو تعديل Supabase/RLS. لا يوجد اعتماد بعد لأنواع أعمدة قاعدة البيانات وسياسات الوصول.

المصدر المرجعي: `weather_phenomena.html`، وخاصة كائن `phenomenonData` في عملية بدء الظاهرة وكائن `updateData` في عملية الإنهاء.

## الحقول المستخدمة فعلياً في المصدر القديم

| المفتاح الأصلي | الاستخدام في المصدر | ملاحظات |
|---|---|---|
| `id` | تحديث السجل بعد البدء | نوع المفتاح غير محسوم هنا |
| `phenomenon_type` | نوع الظاهرة الجوية | نص |
| `phenomenon_date` | تاريخ الظاهرة | تاريخ محلي في المصدر |
| `start_time` | وقت البدء UTC | نص وقت `HH:mm:ss` |
| `end_time` | وقت الانتهاء UTC | فارغ أثناء النشاط |
| `phenomenon_duration` | مدة الظاهرة | تنسيق `HH:mm:ss` |
| `phenomenon_status` | نشطة / منتهية | القيم العربية كما في المصدر |
| `general_notes` | ملاحظات إضافية | نص اختياري |
| `user_email` | بريد المستخدم | يجب استبداله بمرجع هوية موثوق عند التصميم النهائي |
| `user_name` | اسم المستخدم | بيانات عرض، لا تثبت الهوية |
| `station_name` | اسم المحطة | يجب ربطه بمعرّف محطة وتكليف موثوق |
| `user_role` | صفة العمل | لا تستخدم كصلاحية موثوقة |
| `submission_date` | تاريخ الإرسال | تاريخ |
| `submission_time` | وقت الإرسال UTC | وقت |
| `report_type` | نوع التقرير | المصدر يرسل `phenomena_record` |
| `status` | حالة التقرير | المصدر يرسل `submitted` |
| `validation_status` | حالة التحقق | المصدر يرسل `pending` |
| `is_shared_with_station` | إشارة مشاركة المحطة | يجب ألا تسمح للعميل بتجاوز صلاحية المشاركة |
| `shared_at` | وقت المشاركة | timestamp |
| `created_at` | وقت الإنشاء | timestamp |
| `updated_at` | وقت التعديل | timestamp |

## قيم لا ينبغي اعتبارها أعمدة مؤكدة

- `start_time_local` و`end_time_local`: المصدر يضيفهما للعرض المحلي في الذاكرة بعد قراءة السجل؛ لم يثبت أنهما عمودان في قاعدة البيانات.
- `local_start_time`: قيمة مؤقت محلية في الذاكرة وليست حقل تخزين موثوقاً.
- `user_id` و`station_id`: غير موجودين في كائن الإدخال القديم، لكنهما مطلوبان في التصميم الآمن المقترح كمرجعين علائقيين مصدرهما الخادم.

## عقد التحقق المضاف

المسار: `POST /api/v1/observations/phenomena/validate`

الطلب:
```json
{
  "phenomenonType": "مطر خفيف",
  "phenomenonDate": "2026-11-01",
  "startTime": "06:15:00",
  "endTime": null,
  "generalNotes": "ملاحظات اختيارية"
}
```

الاستجابة:
```json
{
  "isValid": true,
  "issues": []
}
```

التحقق الحالي محدود إلى:
- وجود نوع الظاهرة.
- تاريخ صحيح بصيغة `yyyy-MM-dd`.
- وقت بدء صحيح بصيغة `HH:mm:ss`.
- وقت انتهاء اختياري؛ إن أرسل فيجب أن يكون بصيغة `HH:mm:ss`.

هذا endpoint للتحقق فقط، ولا ينشئ سجلاً ولا يصادق على المستخدم أو المحطة ولا يحسب المدة. لم أضف قيوداً غير موجودة في المصدر مثل قائمة مغلقة لأنواع الظواهر أو حد أقصى للملاحظات.

## مقترح التصميم الآمن للمراجعة

قبل إنشاء الجدول، نحتاج اعتماد القرارات التالية:
1. استخدام معرّف مستخدم داخلي موثوق `created_by_user_id` بدلاً من الاعتماد على البريد أو الاسم.
2. استخدام `station_id` كمفتاح أجنبي إلى سجل المحطات؛ اسم المحطة للعرض فقط.
3. تخزين التاريخ والوقت مع تعريف صريح للمنطقة الزمنية للمحطة. المصدر القديم يطرح ثلاث ساعات ثابتة؛ هذا لا يراعي التوقيت الصيفي، لذلك لا يصح تعميمه على جميع المحطات.
4. تحديد ما إذا كانت حالة الظاهرة `phenomenon_status` مستقلة عن دورة اعتماد النشرة `status` و`validation_status`.
5. منع المستخدم من تعيين `user_role` أو `created_by_user_id` أو `station_id` أو حقول المشاركة مباشرة من الطلب.
6. تفعيل RLS وسياسات القراءة/الإضافة/التعديل بعد مراجعة نموذج الهوية والتكليف النشط بالمحطة.
7. ضمان وجود ظاهرة نشطة واحدة فقط لكل مستخدم ومحطة إذا كان هذا هو السلوك التشغيلي المطلوب؛ يحتاج ذلك قراراً وقيداً على مستوى قاعدة البيانات.

## ما لم يتم تنفيذه

- لا توجد migrations أو جداول أو فهارس أو سياسات RLS جديدة.
- لا توجد endpoints لإنشاء/تعديل/قراءة السجلات.
- لا توجد مصادقة فعلية أو صلاحيات مرتبطة بمزود هوية.
- لا توجد مزامنة Angular أو Flutter مع هذا endpoint بعد.


## توضيح التوقيت بعد مراجعة واجهة Angular

في المصدر القديم `weather_phenomena.html` كانت دوال العرض والتحويل تعتمد على ساعة الجهاز، وكان التحويل بين المحلي وUTC يضيف أو يطرح ثلاث ساعات ثابتة بافتراض أن التوقيت هو سوريا GMT+3. هذا الافتراض لا يصلح لجميع المحطات ولا يراعي التوقيت الصيفي.

في واجهة Angular الحالية:
- `phenomenon_date` وحقول `*_time_local` للمعاينة تُشتق من التاريخ والوقت المحليين للجهاز.
- `start_time` و`end_time` تُشتقان من `Date.toISOString()`، أي من لحظة UTC، لكن يُحتفظ بجزء الوقت فقط بصيغة `HH:mm:ss`.
- حقول `*_time_local` و`created_at` في نموذج المعاينة لا تعني أن جميعها حقول تخزين معتمدة؛ الواجهة الحالية لا تحفظ السجل في قاعدة البيانات.

**قيد يجب حسمه قبل تفعيل الحفظ:** زوج التاريخ المحلي ووقت UTC المجرد لا يحدد لحظة الحدث بشكل فريد، خصوصاً عندما يختلف تاريخ UTC عن التاريخ المحلي أو عند عبور منتصف الليل. كما أن ساعة الجهاز ليست مصدراً موثوقاً للمنطقة الزمنية الرسمية للمحطة.

**التوصية للمراجعة فقط، وليست تغييراً معتمداً:** اعتماد معرّفات مناطق IANA للمحطات (مثل `Asia/Damascus`) كمعلومة إعداد موثوقة، وتخزين لحظات البدء والانتهاء كـ timestamps كاملة بتوقيت UTC. ويمكن الاحتفاظ بحقول التاريخ والوقت القديمة للتوافق مع المصدر بعد توثيق معناها وقواعد تحويلها. لا ينبغي إجراء تحويل ثابت بمقدار ثلاث ساعات في الواجهة أو الخادم.

لم يُغيّر هذا التوضيح عقد الطلب أو قاعدة البيانات أو قواعد التحقق، ولم تُنشأ migration أو سياسات RLS.


## جدول مطابقة مسميات واجهة الظواهر ومعرّفات المصدر

الجدول التالي يثبت مسميات عناصر الإدخال والتحكم الأساسية كما وردت في `weather_phenomena.html`، ويبيّن طريقة تمثيلها في Angular. معرّفات DOM الأصلية موثقة حتى لا تختلط أسماء العرض بمفاتيح البيانات:

| المسمى الأصلي | معرّف المصدر الأصلي | تمثيله في Angular الحالي | الحالة |
|---|---|---|---|
| نوع الظاهرة الجوية | `phenomenonType` | `id="phenomenonType"` / `phenomenonType` | مطابق |
| اقتراحات | `suggestBtn` | `showSuggestions` و`chooseSuggestion()` | سلوك Angular بديل؛ المسمى محفوظ |
| بدء الظاهرة | `startBtn` | `startPhenomenon()` | المسمى محفوظ |
| إيقاف مؤقت | `pauseBtn` | `togglePause()` | المسمى محفوظ |
| إنهاء الظاهرة | `stopBtn` | `stopPhenomenon()` | المسمى محفوظ |
| وقت البدء (UTC) | `startTimeDisplay` و`startTime` | `activePhenomenon.start_time` / `lastEnded.start_time` | القيمة معروضة؛ لا يوجد معرّف DOM مطابق |
| وقت الانتهاء (UTC) | `endTimeDisplay` و`endTime` | `activePhenomenon.end_time` / `lastEnded.end_time` | القيمة معروضة؛ لا يوجد معرّف DOM مطابق |
| وقت البدء (محلي) | `startTimeLocalDisplay` | `start_time_local` | القيمة معروضة؛ لا يوجد معرّف DOM مطابق |

قيم الفلترة الأصلية `all`, `active`, `ended`, `my`, `today` محفوظة في Angular. يجب عدم اعتبار أسماء خصائص TypeScript بديلاً عن مفاتيح قاعدة البيانات؛ مفاتيح السجل الأصلية موثقة بصورة منفصلة في جدول الحقول أعلاه.

## مطابقة الوظائف بين المصدر الأصلي وواجهة Angular

تمت مراجعة معالجات الأحداث في `weather_phenomena.html` ومقابلتها مع `phenomena-input.component.ts`. هذه الفروق موثقة حتى لا تُفهم معاينة Angular على أنها تنفيذ مكتمل للوظيفة الأصلية:

| الوظيفة | السلوك في المصدر الأصلي | السلوك الحالي في Angular | نتيجة المطابقة |
|---|---|---|---|
| زر تحديث | يستدعي `loadPhenomena()` ويعيد قراءة جدول `weather_phenomena` للمحطة من Supabase | يستدعي `refreshLocalView()` ويحدّث وقت العرض ورسالة المعاينة فقط | غير مطابق وظيفياً؛ لا يوجد اتصال بيانات في Angular |
| بدء الظاهرة | يشترط وجود `currentUser`، ثم ينشئ سجلاً في `weather_phenomena` ويستقبل `id` من قاعدة البيانات | ينشئ كائناً محلياً بمعرّف `local_*` ويضيفه إلى مصفوفة الجلسة | معاينة محلية فقط؛ لا يوجد تحقق هوية أو حفظ |
| إنهاء الظاهرة | يشترط وجود `currentUser`، ثم يحدّث السجل المحفوظ باستخدام `id` | يحدّث العنصر داخل مصفوفة الجلسة | معاينة محلية فقط؛ لا يوجد تحديث في قاعدة البيانات |
| إيقاف مؤقت | يبدّل مظهر الزر ونصه ويعرض إشعاراً؛ لا يوقف مؤقت المدة ولا يعلّق احتسابها | يبدّل حالة العرض، بينما يستمر احتساب المدة من وقت البدء | مطابق في أثر احتساب المدة بعد التصحيح؛ يلزم مقارنة تفاصيل الإشعارات ومظهر الزر بصرياً |
| الفلترة | يطبق `all`, `active`, `ended`, `my`, `today` على البيانات المحمّلة من المحطة | يحتفظ بالقيم نفسها، لكن يفلتر سجلات المعاينة المحلية؛ فلتر `my` يعرض قائمة فارغة حتى ربط الهوية | القيم محفوظة؛ مصدر البيانات ونطاق الفلترة غير متطابقين حالياً |

### حقول عملية الإدخال الأصلية

عملية البدء الأصلية ترسل إلى جدول `weather_phenomena` الحقول التالية كما هي في كائن `phenomenonData`:

`phenomenon_type`, `phenomenon_date`, `start_time`, `phenomenon_status`, `general_notes`, `user_email`, `user_name`, `station_name`, `user_role`, `submission_date`, `submission_time`, `report_type`, `status`, `validation_status`, `is_shared_with_station`, `shared_at`, `created_at`, `updated_at`.

وعملية الإنهاء الأصلية ترسل في `updateData`:

`end_time`, `phenomenon_duration`, `phenomenon_status`, `submission_date`, `submission_time`, `updated_at`.

هذه قائمة مرجعية للمطابقة فقط، وليست موافقة على تمرير حقول الهوية أو الدور أو المشاركة من العميل إلى API. يجب أن يحدد الخادم هوية المستخدم وصلاحية المحطة وسياسة المشاركة من سياق موثوق قبل تنفيذ أي حفظ.

### قرارات التنفيذ المؤجلة

- لا تُحوّل وظيفة «تحديث» إلى استدعاء قاعدة بيانات قبل وجود endpoint قراءة معتمد ومصادقة وتفويض على مستوى المحطة.
- لا تُحوّل البدء أو الإنهاء إلى حفظ فعلي قبل اعتماد CRUD API وعقد الطلب والاستجابة وسياسات الصلاحيات.
- لا تُعرض أرقام «ظواهري النشطة» على أنها بيانات حقيقية قبل ربط هوية المستخدم ومصدر البيانات.
- تظل الواجهة الحالية موسومة بوضوح بأنها معاينة محلية غير محفوظة؛ لا ينبغي إزالة هذا التنبيه حتى يكتمل الربط الفعلي.

## تدقيق إضافي لمعرّفات DOM الأصلية غير الممثلة في Angular

أظهر استخراج جميع معرّفات `id` من ملف المصدر 59 معرّفاً، بما فيها عناصر تُنشأ ديناميكياً. الجدول السابق يغطي الحقول الأساسية فقط، وليس كامل الواجهة. العناصر التالية ما زالت غائبة عن مكوّن Angular الحالي أو لا تملك مقابلاً وظيفياً مباشراً:

| معرّف المصدر | العنصر/المسمى في المصدر | وضع Angular الحالي |
|---|---|---|
| `mobileMenuBtn` | زر القائمة للجوال | غير ممثل في مكوّن الظواهر |
| `mobileOverlay` | طبقة التعتيم للجوال | غير ممثلة |
| `mainSidebar` | القائمة الجانبية | تُدار القائمة العامة من التطبيق؛ لا يوجد عنصر مطابق داخل المكوّن |
| `sidebarUser` | اسم المستخدم في القائمة الجانبية | غير مربوط بهوية مستخدم |
| `sidebarStation` | المحطة في القائمة الجانبية | غير مربوط ببيانات محطة |
| `sidebarMenu` | قائمة التنقل الرئيسية | خارج مكوّن الظواهر؛ يجب أن تبقى قائمة التطبيق الواحدة |
| `sidebarActiveCount` | عدد الظواهر النشطة في القائمة الجانبية | غير ممثل في مكوّن الظواهر |
| `sidebarTodayCount` | عدد ظواهر اليوم في القائمة الجانبية | غير ممثل في مكوّن الظواهر |
| `notificationContainer` | حاوية الإشعارات | تستخدم Angular رسالة داخلية `message`؛ ليست مطابقة لنظام إشعارات المصدر |
| `loadingOverlay` و`loadingMessage` | طبقة التحميل ورسالتها | غير ممثلتين |
| `realtimeIndicator` | مؤشر البث المباشر | غير ممثل؛ لا يوجد اشتراك Realtime في Angular |
| `loginWarning` | تحذير تسجيل الدخول | غير ممثل؛ لا توجد مصادقة مربوطة |
| `mainContainer` | حاوية الواجهة الرئيسية | لا يوجد عنصر مطابق بالمعرّف |
| `connectionStatus` | حالة الاتصال | غير ممثلة؛ المعاينة لا تتصل بمصدر بيانات |
| `currentUser`, `currentStation`, `currentRole` | المستخدم والمحطة والصفة في الرأس | غير ممثلة ببيانات حقيقية |
| `currentStatusText` | حالة الظاهرة الحالية | ممثلة نصياً عبر `statusText` دون معرّف DOM مطابق |
| `statusIndicator` | مؤشر حالة الظاهرة | ممثل جزئياً عبر أصناف CSS للحالة |
| `statusDetails` | تفاصيل حالة الظاهرة | ممثلة نصياً عبر `statusDetails` |
| `durationContainer`, `currentDuration` | حاوية المدة والمدة الحالية | المدة معروضة عبر `currentDuration`؛ لا يوجد تطابق للمعرّفين |
| `suggestions` | قائمة اقتراحات أنواع الظواهر | ممثلة عبر `showSuggestions` و`suggestions` |
| `filterInfo`, `filterInfoText` | معلومات الفلترة ونصها | ممثلة عبر `filterInfo` كنص، دون بنية DOM الأصلية |
| `startFirstBtn` | ابدأ تسجيل أول ظاهرة | ممثل بزر في الحالة الفارغة، دون معرّف مطابق |
| `stationStats`, `statsLoading`, `statsGrid` | إحصائيات تقارير المحطة وحالة تحميلها | قسم إحصائيات بديل؛ القيم الفعلية غير متاحة |
| `whatsappModal`, `confirmWhatsApp` | نافذة تأكيد الإرسال إلى واتساب وزر التأكيد | غير ممثلين في Angular الحالي |

المعرّفات التي تحتوي على `count-hourly`, `count-soil`, `count-agri`, `count-climate`, `count-daily`, و`count-rain` تخص عناصر إحصائيات تقارير المحطة التي تُنشأ/تُعرض في منطقة الإحصائيات. لا تُعامل كحقول إدخال لجدول الظواهر الجوية.

هذا التدقيق يثبت وجود فجوات واجهة ووظائف، ولا يجيز إضافة قائمة جانبية ثانية أو اختراع بيانات مستخدم/محطة أو إظهار حالة اتصال أو بث مباشر غير حقيقية. يجب استعادة العناصر بحسب موضعها ووظيفتها في المصدر الأصلي عند تنفيذ المطابقة البصرية والوظيفية.


## استكمال مطابقة معرّفات حالة الظاهرة والسجل والإحصائيات

في مراجعة Angular الأخيرة تمت إضافة معرّفات DOM الأصلية إلى العناصر المقابلة الموجودة فعلياً، دون إنشاء عناصر وهمية أو تكرار القائمة الجانبية:

| معرّف المصدر الأصلي | العنصر الأصلي | العنصر المقابل في Angular بعد التعديل | حالة المطابقة |
|---|---|---|---|
| `currentStatusText` | نص حالة الظاهرة الحالية | عنوان الحالة `statusText` | معرّف مطابق |
| `statusIndicator` | مؤشر حالة الظاهرة | نقطة حالة مرتبطة بحالة وجود ظاهرة وبحالة الإيقاف المؤقت | معرّف وسلوك عرض ممثلان |
| `statusDetails` | تفاصيل حالة الظاهرة | النص `statusDetails` | معرّف مطابق |
| `durationContainer` | حاوية مدة الظاهرة | حاوية تظهر عند وجود ظاهرة نشطة | معرّف مطابق |
| `currentDuration` | قيمة المدة الحالية | `currentDuration` | معرّف مطابق |
| `suggestions` | حاوية اقتراحات أنواع الظواهر | حاوية الاقتراحات الشرطية | معرّف مطابق |
| `filterInfo` | حاوية معلومات الفلترة | حاوية معلومات الفلترة | معرّف مطابق |
| `filterInfoText` | نص معلومات الفلترة | النص المحسوب `filterInfo` | معرّف مطابق |
| `phenomenaList` | قائمة الظواهر | حاوية سجلات المعاينة الظاهرة | معرّف مطابق؛ مصدر البيانات محلي |
| `emptyState` | حالة القائمة الفارغة | قالب الحالة الفارغة | معرّف مطابق |
| `startFirstBtn` | زر بدء أول ظاهرة | زر بدء المعاينة الأولى | معرّف مطابق؛ لا ينشئ سجلاً محفوظاً |
| `stationStats` | قسم إحصائيات تقارير المحطة | قسم الإحصائيات غير المتاحة | معرّف مطابق؛ القيم الفعلية غير مربوطة |
| `statsGrid` | شبكة إحصائيات المحطة | شبكة القيم التوضيحية غير المتاحة | معرّف مطابق؛ ليست بيانات فعلية |
| `lastUpdateTime` | وقت آخر تحديث للسجل | وقت تحديث عرض المعاينة | معرّف مطابق؛ لا يعني إعادة جلب من الخادم |

أُضيفت تنسيقات مؤشر الحالة بما يميّز الحالة النشطة والإيقاف المؤقت بصرياً. لا تزال المطابقة الوظيفية غير مكتملة في النقاط التي تعتمد على خدمات غير موجودة: المصادقة، بيانات المستخدم والمحطة، التحميل الحقيقي، الاتصال، Realtime، قراءة السجل من قاعدة البيانات، وإحصائيات المحطة. لا تُعد إضافة معرّف DOM بحد ذاتها دليلاً على تنفيذ وظيفة الخادم المقابلة.


### استكمال معرّفات الإحصائيات وأزرار التحكم وعرض الأوقات

استُكملت مطابقة العناصر الموجودة فعلياً في واجهة Angular بإضافة المعرّفات التالية:

| معرّف المصدر | المسمى الأصلي | موضعه في Angular |
|---|---|---|
| `totalPhenomena` | إجمالي الظواهر | قيمة إجمالي سجلات المعاينة |
| `activePhenomena` | ظواهر نشطة | قيمة عدد السجلات النشطة في المعاينة |
| `myActivePhenomena` | ظواهري النشطة | قيمة غير متاحة وتظهر `—` حتى ربط الهوية |
| `todayPhenomena` | اليوم | عدد سجلات المعاينة بتاريخ الجهاز الحالي |
| `suggestBtn` | اقتراحات | زر إظهار/إخفاء الاقتراحات |
| `startBtn` | بدء الظاهرة | زر بدء المعاينة المحلية |
| `pauseBtn` | إيقاف مؤقت | زر تبديل حالة الإيقاف المؤقت |
| `stopBtn` | إنهاء الظاهرة | زر إنهاء المعاينة المحلية |
| `startTimeDisplay` | وقت البدء (UTC) | قيمة وقت البدء المعروضة |
| `endTimeDisplay` | وقت الانتهاء (UTC) | قيمة وقت الانتهاء المعروضة |
| `startTimeLocalDisplay` | وقت البدء (محلي) | قيمة وقت البدء المحلي المعروضة |
| `endTimeLocalDisplay` | وقت الانتهاء (محلي) | قيمة وقت الانتهاء المحلي المعروضة |
| `refreshBtn` | تحديث | زر تحديث عرض المعاينة المحلية |

لم تتم إضافة معرّفي المصدر `startTime` و`endTime` كحقلي إدخال مخفيين؛ فهما في المصدر القديم حقلا وقت مخفيان منفصلان عن عنصري العرض، بينما Angular يعرض القيم حالياً ولا يرسل نموذجاً إلى API. إضافتهما كحقول مخفية الآن قد توحي خطأً بوجود عقد إرسال أو حفظ. كما لم تُضف معرّفات `count-hourly` و`count-soil` و`count-agri` و`count-climate` و`count-daily` و`count-rain` لأن القيم المقابلة لا تأتي من مصدر إحصائي فعلي؛ يجب ربط البيانات أولاً بدلاً من اختلاق عدادات.


### استعادة حقلي الوقت المخفيين للتوافق مع المصدر

أُضيف العنصران التاليان إلى قالب Angular كحقلي HTML مخفيين مرتبطين بقيم المعاينة الحالية/آخر ظاهرة منتهية:

| معرّف المصدر | الاسم | الربط في Angular |
|---|---|---|
| `startTime` | `startTime` | `activePhenomenon.start_time` أو `lastEnded.start_time` |
| `endTime` | `endTime` | `activePhenomenon.end_time` أو `lastEnded.end_time` |

الغرض هو استعادة معرّفات الحقول وقيمها المقابلة كما في المصدر، وليس تفعيل إرسال نموذج أو حفظ بيانات. لا يوجد حالياً نموذج HTML يرسل هذه القيم إلى الخادم ولا endpoint لإنشاء سجل. تبقى حقول الوقت المحلية حقول عرض فقط، كما هو موضح في الجدول السابق.
