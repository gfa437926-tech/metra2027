# تدقيق تشغيلي للأدوار والصلاحيات — METRA 2027

**المصدر الوحيد للأدوار المُعرَّفة:** `docs/security/role-permission-matrix.md` والكود المرتبط (لا أدوار مخترعة).
**التاريخ المرجعي:** HEAD الفرع `feat/phenomenon-observation-submit-2026-11-16`.

## 1. الأدوار الموجودة فعلياً في السياسة

| الرمز الإنجليزي (الكود) | دلالة تشغيلية تقريبية | صلاحيات observation / station المُدرجة في المصفوفة |
|---|---|---|
| `observer` | الراصد الجوي | `observation.create`, `observation.edit_own_draft`, `observation.submit` |
| `station_head` | رئيس المحطة | `observation.review`, `observation.return_for_correction`, `registrations.station.approve`, `users.station.view`, `users.station.manage` |
| `station_auditor` | المدقق (مستوى محطة) | `observation.review`, `observation.return_for_correction` |
| `chief_auditor` | المدقق الأعلى | `observation.approve`, `observation.return_for_correction` |
| `network_director` | مدير الشبكة / كتالوج | `stations.catalogue.review` (لا صلاحيات observation مباشرة) |
| `statistics_director` | مدير الإحصاء / المناخ | لا صلاحيات observation مباشرة في المصفوفة الحالية |
| `aftn_operator` | فني / مشغّل اتصالات | لا صلاحيات observation مباشرة |
| `system_admin` | مدير النظام | `registrations.system.approve`, `users.station.view`, `users.station.manage` (لا bypass رصد) |

**ملاحظة صريحة:** الأسماء العربية في طلب التدقيق (مدير المناخ، مدير الرصد، فني المحطات…) **لا تُعرَّف كرموز أدوار جديدة** في الكود. أي مطابقة عربية↔رمز يجب أن تُعتمد رسمياً قبل إضافتها إلى قاعدة البيانات أو الواجهة.

## 2. ما يراه كل دور في الواجهة الحالية (Flutter)

الواجهة **تخفي الوجهات التشغيلية حسب رموز الصلاحيات من Access Context** (لا حسب اسم الدور). الخادم يبقى المرجع النهائي (401/403) و`MetraErrorPresenter` يعرض رسائل عربية.

| المنطقة | سلوك الواجهة | فرض الخادم |
|---|---|---|
| دليل المحطات | متاح بعد الدخول + شارة/فلتر «محطاتي» عند توفر السياق | قائمة الدليل؛ العمليات تُفرض لاحقاً |
| وحدة الرصد (ساعي/يومي/ظاهرة) | تظهر عند صلاحيات رصد/مراجعة؛ gate لكل محطة | `observation.create` على مسار الإرسال |
| مراجعة الأرصاد | تبويب يظهر عند رموز المراجعة على المحطة | review / approve / return |
| إدارة المحطة | وجهة + gate حسب رموز الإدارة | `users.station.*` + موافقات التسجيل |
| CLIMATOL / AI / أجهزة / تقارير | ظاهرة كـ placeholders مع إشعار offline | لا API إنتاجي |
| النماذج السبعة الكتالوجات | تحقق محلي + مسودة محلية | لا إرسال |

**Access Context:** `GET /api/v1/me/access-context` منفَّذ (JWT `sub` + assignments + RPC صلاحيات). `accountState` يبقى `unknown` حتى مصدر معتمد — انظر `SECURITY-VALIDATE-SUBMIT-ACCOUNT-STATE.md`.

## 3. إدارة المستخدمين — ما يمكن تنفيذه الآن

### منفَّذ ومربوط

- عرض مستخدمي المحطة (اسم، دور التعيين، حالة، هاتف عند التوفر).
- عرض طلبات التسجيل المعلقة واعتماد/رفض مع سبب إلزامي للرفض.
- منع الإجراءات المتكررة (`_processingRequestIds`).
- حالات التحميل والفراغ والأخطاء العربية.
- سجل تدقيق المحطة (قراءة فقط).
- طابور أرصاد للمراجعة (قراءة + قرار من شاشة المراجعة).

### غير منفَّذ (ينقص عقد أو موافقة)

| الوظيفة | السبب |
|---|---|
| بحث/تصفية عالمي للمستخدمين | لا endpoint خارج نطاق المحطة |
| تعديل دور أو صلاحية من الواجهة | لا عقود كتابة لأدوار/منح من مسار المحطة |
| عرض تفاصيل مستخدم موسّعة (بريد كامل، منح فردية) | الدليل مقيّد عمداً (لا بريد/أسرار) |
| إدارة عضويات السلطة ومنح الصلاحيات | عقود authority موجودة في API؛ واجهة Flutter غير مكتملة |

## 4. تدقيق الواجهات (ملخص سريع)

| الشاشة | أزرار بلا وظيفة؟ | بيانات تجريبية كحقيقة؟ | حالات تحميل/فراغ/خطأ | RTL |
|---|---|---|---|---|
| تسجيل الدخول / استعادة كلمة المرور | لا | لا | نعم | نعم |
| الرئيسية + التنقل التكيّفي | لا | لا | رسائل توضيحية | نعم |
| دليل المحطات | لا | لا | نعم | نعم |
| الرصد الساعي/اليومي/الظاهرة | لا (إرسال حقيقي) | لا | نعم + drafts | نعم |
| مراجعة الأرصاد | لا | لا | نعم + حماية تزامن | نعم |
| إدارة المحطة | لا | لا | نعم + حماية تزامن | نعم |
| كتالوج النماذج السبعة | إرسال معطّل بإشعار صريح | لا | محلي | نعم |
| CLIMATOL / AI / أجهزة / تقارير | أزرار `onPressed: null` + `_ServiceNotice` | قيم «—» فقط | إشعار عدم اتصال | نعم |
| الإعدادات | خروج فقط | لا | — | نعم |

لا توجد روابط تنقل معطّلة داخل الـ shell؛ الوجهات التي تحتاج محطة تعرض صفحة توضيحية.

## 5. جاهزية النشر (دون نشر فعلي)

راجع:

- `docs/deployment/FLUTTER-WEB-PRODUCTION-RELEASE.md`
- `docs/deployment/MULTI-ENVIRONMENT-HOSTING.md`
- `backend/DEPLOYMENT.md`

| بند | الحالة |
|---|---|
| Flutter Web Release workflow | موجود؛ يحتاج أسرار `METRA_API_BASE_URL` + Supabase URL/publishable فقط |
| رفض service_role في العميل | مُطبَّق في التوثيق والتحقق |
| شاشة غياب الإعدادات | `MetraConfigurationScreen` |
| HTTPS / CORS / JWT | مسؤولية استضافة API؛ موثّقة كبوابات إصدار |
| سجلات أخطاء حساسة | رسائل عربية عامة عبر `MetraErrorPresenter`؛ لا تسريب service role |
| Android / iOS signed builds | غير مُنفَّذة في هذا الفرع كمسار إصدار كامل |

**لا نشر إنتاجي في هذا العمل.**

## 6. خلاصة الفجوات التي تحتاج موافقتك

1. عقود حفظ للنماذج السبعة (أو رفض رسمي لها كواجهة إدخال فقط).
2. عقد access-context لإخفاء الوجهات حسب الصلاحية.
3. واجهة Flutter لإدارة السلطات/العضويات/المنح (العقود موجودة جزئياً على API).
4. مطابقة رسمية للأسماء العربية ↔ رموز الأدوار الثمانية الحالية (أو إضافة أدوار بـ migration معتمد لاحقاً).
5. أي تعديل صلاحيات أو عضويات من الواجهة يتجاوز المسارات الحالية.
