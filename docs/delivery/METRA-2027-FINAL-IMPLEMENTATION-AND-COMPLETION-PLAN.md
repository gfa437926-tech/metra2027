## 1) ملخص تنفيذي صادق

المشروع **ليس** نموذجاً أولياً فارغاً: يوجد Backend .NET واسع، Angular، Flutter، عقود رصد، عزل محطات، أعطال/دعم، أرشفة يدوية، CI أخضر على فرع العمل.

**إعلان «اكتمال المستودع ضمن القيود» ≠ «إطلاق تشغيلي».**

1. **عدم دمج** المسارات المعتمدة إلى `main` بعد مراجعة.

5. وحدات مناخي/مطري/تربة/زراعي بلا عقود معتمدة.
6. Staging + أسرار + قبول تشغيلي متعدد المحطات.
7. بعض PR الموازية (#14–#16) قد تحتوي واجهات أصلية لم تُدمَج بعد في فرع العمل.

### القرار
إيقاف توسيع واجهات Angular مؤقتاً، وتوجيه العمل الوظيفي والاختباري إلى إكمال تطبيق Flutter أولاً. لا يعني ذلك حذف Angular أو إيقاف إصلاح CI المشترك عند الحاجة.

### ملاحظة تدقيق مهمة
يحتوي الفرع على مسارين Flutter:
- `flutter-app/` — المسار الذي يعرّفه README بوصفه عميل Flutter المستقل، ويحتوي شاشات إضافية مثل forecasting وadmin وreports.
- `mobile/metra_mobile/` — شجرة Flutter أخرى أصغر ومتداخلة وظيفياً.

يجب حسم المسار الرسمي للموبايل بمراجعة تاريخ الملفات وPRs والـCI قبل نقل أو دمج أي ملفات. لا يجوز دمج الشجرتين عشوائياً أو حذف أي منهما قبل إثبات مصدر الحقيقة والتوافق. ويجب أن يظل CI قادراً على كشف الاختلافات بين المسارين بدلاً من إخفائها.

### نطاق إكمال Flutter
1. جرد كل شاشة ومسار تنقل وميزة مقابل المواصفات والواجهات المرجعية.
2. تثبيت بنية تطبيق موحدة: المصادقة، shell، التنقل، القوائم، اختيار المحطة، الثيم العربي RTL والاستجابة.
3. إكمال واجهات كل الأدوار والصلاحيات دون منح صلاحيات عبر الواجهة.
4. إكمال الرصد الساعي واليومي والظواهر، المراجعة والإرجاع وإعادة التقديم.
5. إكمال دليل المحطات، الصيانة، الأعطال، الدعم، التسجيل والتعيينات، الأرشفة والتقارير حسب العقود المتاحة.
6. إكمال مركز التنبؤ الجوي بعد ربطه بمصادر موثوقة وعقود معتمدة؛ لا تعرض بيانات وهمية على أنها حقيقية.
7. إضافة حالات التحميل والفراغ والخطأ وانقطاع الاتصال والبيانات المتأخرة وغير المكتملة.
8. اختبارات widget/unit/integration، تحليل Flutter، وبناء Android تجريبي عند توفر البيئة.
9. مراجعة أمن التخزين والجلسات وHTTPS وعدم تضمين مفاتيح إدارية أو أسرار.
10. توثيق كل شاشة وحالتها ودليل قبولها.

### معايير اعتبار Flutter مكتملاً
- لا توجد شاشة مطلوبة مفقودة أو مجرد placeholder غير موثق.
- كل عناصر التنقل تؤدي إلى وظائف حقيقية أو تعرض حالة عدم الإتاحة بوضوح.
- كل شاشة مرتبطة بعقد API موجود، أو موثقة كغير متاحة بانتظار قرار/Backend.
- تكافؤ الوظائف المطلوبة بين الأدوار.
- نجاح `flutter analyze` و`flutter test` وبناء Android Release/Debug وفق البيئة.
- عدم وجود بيانات رصد مختلقة أو إحداثيات غير موثقة.
- مراجعة RTL وإمكانية الاستخدام على الهاتف واللوحي.
- تقرير قبول لكل وحدة مع أدلة CI.
