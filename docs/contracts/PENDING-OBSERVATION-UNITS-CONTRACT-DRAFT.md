# مسودة عقود الوحدات الناقصة (بدون اختراع قواعد أرصاد)

**الحالة:** مراجعة / قرارات معلّقة — ليست عقد قبول نهائي.  
**API الحالي يقبل للإرسال:** `hourly` | `daily` | `phenomenon` فقط.  
**UTC:** إلزامي في كل تخزين/عرض/تحقق زمني.

## 1) المناخي (Climate aggregates)

| البند | الوضع |
|---|---|
| واجهة Angular | غلاف صريح غير مربوط |
| Flutter | غير مربوط |
| API submit type | غير موجود |
| الحقول | **غير محسومة** — تحتاج صيغ تجميع معتمدة (معدلات، مجاميع، فترات) |
| أسئلة للمالك | ما مصدر السجلات الخام؟ ما نافذة التجميع؟ من يعتمد التقرير؟ |

## 2) السنوي (Annual)

| البند | الوضع |
|---|---|
| واجهة | غلاف غير مربوط |
| API | غير موجود |
| أسئلة | هل هو تجميع من اليومي/الساعي فقط أم نموذج إدخال مستقل؟ |

## 3) المطري (Rainfall bulletin)

| البند | الوضع |
|---|---|
| واجهة | غلاف غير مربوط |
| API | غير موجود كنوع مستقل |
| ملاحظات مصدرية | قد تتقاطع مع حقول الهطول في الساعي/اليومي |
| أسئلة | هل النشرة المطرية كيان مستقل أم عرض مشتق؟ |

## 4) حرارة التربة (Soil temperature)

| البند | الوضع |
|---|---|
| واجهة | غلاف غير مربوط |
| API | غير موجود |
| مرشّح حقول من المصدر (للمراجعة فقط) | أعماق 5/10/20/... سم؛ قيم ±dd.d أو `#`؛ وقت UTC |
| أسئلة | أي أعماق إلزامية حسب برنامج المحطة؟ |

## 5) الزراعي (Agricultural monthly)

| البند | الوضع |
|---|---|
| واجهة | غلاف غير مربوط |
| API | غير موجود |
| أسئلة | قائمة الحقول الزراعية الرسمية المعتمدة؛ دور الموافقة |

## 6) ما يُنفَّذ دون انتظار هذه القرارات

- الإبقاء على أغلفة صادقة (لا أرقام وهمية).
- تقوية hourly/daily/phenomenon + عزل المحطات.
- فهرس حقول مرجعي من المصدر كـ UI catalogue فقط (PR #15/#16) دون تفعيل submit لأنواع غير مدعومة.

## 7) معيار قبول لاحق لكل وحدة (بعد اعتماد العقد)

1. جدول حقول + إلزامية/شرطية حسب برنامج المحطة  
2. `Request`/`Response` API  
3. تحقق خادمي مطابق للعميل  
4. دورة إدخال→مراجعة→اعتماد/إرجاع  
5. صلاحيات محطة  
6. اختبارات قبول + عزل  
7. لا تطبيق SQL دون موافقة منفصلة إن لزم جدول جديد
