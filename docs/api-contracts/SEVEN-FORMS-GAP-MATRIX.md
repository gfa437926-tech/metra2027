# مصفوفة فجوات النماذج السبعة (كتالوج PR #53)

**حالة الحفظ الخادمي:** غير معتمدة — واجهة Flutter محلية فقط (`CatalogObservationScreen` + لافتة «تحقق محلي فقط»).  
**مرجع الحقول:** `ObservationFieldCatalogs` في Flutter.  
**لا جداول / RPC / migrations في هذا المستند — قائمة قرارات فقط.**

العقود المعتمدة للحفظ اليوم: `hourly` | `daily` | `phenomenon` فقط  
(`docs/api-contracts/UNIFIED-OBSERVATION-API-CONTRACTS.md`).

## تفصيل لكل نموذج

### 1) agricultural — الرصد الزراعي

| بند | الوضع |
|---|---|
| حقول معتمدة | 31 من الكتالوج (حرارة، رطوبة، ظواهر زراعية، إقرار، …) |
| مطلوبة | `dew`, `fog`, `hail`, `sandstorm`, `responsibilityAgreement` |
| اختيارية | بقية الحقول بما فيها `observerNotes` والتواريخ |
| تحقق | محلي عبر `MetraObservationForm` + حدود kind/min/max في الكتالوج |
| مصدر بيانات | إدخال يدوي للراصد؛ لا API قراءة |
| صلاحية مقترحة لاحقاً | `observation.create` على المحطة **أو** رمز أدق بعد موافقة |
| الواجهة | تبويب في `ObservationWorkspaceScreen` + لافتة محلي |
| ينقص للاتصال الخادمي | نوع `observationType` معتمد، validate، مسار حفظ، قواعد مجال خادمية |
| قرارات/موافقة | جدول/RPC أو توسيع `metra_submit_observation`؛ صلاحية؛ عدم خلطه مع hourly |

## قاسم مشترك لما ينقص قبل أي ربط خادمي

1. موافقة على **observationType** (أو مورد غير observation) لكل رمز.  
2. موافقة على **صلاحية** (إعادة استخدام `observation.create` أو رموز أدق).  
3. قواعد تحقق خادمية رسمية (لا الاكتفاء بالكتالوج المحلي).  
4. توسيع guard الإرسال (`ObservationSubmissionRequestGuard` يقبل اليوم hourly|daily|phenomenon فقط).  
5. RPC/جدول أو توسيع معتمد لـ `metra_submit_observation` — **ليس في هذا الفرع دون موافقة**.  
6. اختبارات .NET + Flutter بعد اعتماد العقد.

**الوضع الآمن الحالي:** الإبقاء على التحقق المحلي + منع ادّعاء الحفظ الخادمي (مُنفَّذ في الواجهة).
