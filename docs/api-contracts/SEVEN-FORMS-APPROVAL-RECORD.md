# سجل اعتماد قرارات D1–D7

**التاريخ:** 2026-11-18  
**الفرع:** `feat/phenomenon-observation-submit-2026-11-16`  
**الحالة:** معتمد من مالك المشروع وفق الشروط أدناه.

## القرارات المعتمدة

| قرار | الاعتماد |
|---|---|
| **D1** تخزين | فصل تخزين الرصد عن تخزين الأعطال |
| **D2** أعطال | **تأجيل** صلاحيات ودورة الأعطال حتى اعتماد تصميم تشغيلي مستقل |
| **D3** إنشاء | `observer` منشئ مبدئي للنماذج الرصدية الأربعة؛ **دون** منح صلاحيات إنتاج إضافية في هذه الموافقة |
| **D4** hourlyclimate | مستقل بالكامل عن `hourly` |
| **D5** حدود رقمية | عدم اعتماد حدود أرصادية غير موثقة |
| **D6** مرفقات | مؤجّلة |
| **D7** ترتيب | 1) rainfall + soil → 2) agricultural → 3) hourlyclimate → (الأعطال لاحقاً) |

## قيود صريحة من المالك (سارية)

هذه الموافقة **لا** تسمح دون موافقة مستقلة لاحقة بـ:

- تعديل Supabase schema
- تعديل RLS
- إنشاء أو تعديل RPC
- migrations
- منح أو تغيير صلاحيات الإنتاج (`metra_role_permissions` أو ما يعادلها)

## ما يُسمح به فوراً ضمن هذه الموافقة

- توثيق الاعتماد وخطط التنفيذ.
- تحسين التحقق والكتالوج المحلي لـ rainfall/soil (ثم agricultural ثم hourlyclimate) دون اختراع حدود رقمية غير موثقة.
- اختبارات Flutter محلية للتحقق والمسودات.
- إعداد مواصفات تنفيذ Backend/DB كـ **مسودات مهام** فقط حتى موافقة DB/API مستقلة.

## ما يبقى ممنوعاً حتى موافقة لاحقة

- قبول `observationType=rainfall|soil|…` في `ObservationSubmissionRequestGuard` مع مسار حفظ حقيقي.
- أي endpoint أو validate خادمي جديد مرتبط بالأنواع الجديدة.
- أي تغيير RPC لـ `metra_submit_observation` أو ما شابه.
