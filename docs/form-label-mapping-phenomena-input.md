المصدر المرجعي: `weather_phenomena.html` في جذر المستودع.  
ملاحظة مصدرية: الصفحة الأصلية تحتوي رابطاً إلى `phenomena_input.html` من صفحة العرض، لكن هذا الملف غير موجود في شجرة المستودع. لذلك نُقلت صفحة التسجيل الموجودة فعلياً في `weather_phenomena.html`.  
مكوّن Angular: `angular-app/src/app/features/phenomena/phenomena-input.component.ts`  
المسار: `/phenomena/input`

## التحويل الزمني في المصدر

- `localTimeToUTC`: طرح 3 ساعات من الوقت المحلي، وإضافة 24 عند تجاوز منتصف الليل إلى الخلف.
- `utcToLocalTime`: إضافة 3 ساعات، وطرح 24 عند تجاوز نهاية اليوم.
- تنسيق الوقت: `HH:mm:ss`.
- حساب المدة: `HH:mm:ss`.
- المصدر يستخدم ساعة النظام المحلية ثم يطبق فرق +03:00 يدوياً في التحويل؛ تم الاحتفاظ بهذا السلوك في المعاينة، ويجب حسم المنطقة الزمنية الرسمية للمحطة في API قبل اعتماد التسجيل الحقيقي.

## حالة التنفيذ

- نُقلت شاشة التحكم بالظاهرة، حالة الظاهرة الحالية، حقل النوع والاقتراحات، الأزرار الثلاثة، الأوقات المحلية وUTC، الملاحظات، سجل الجلسة والفلاتر، العدادات، وإحصائيات المحطة.
- أزرار البدء والإيقاف المؤقت والاستئناف والإنهاء تعمل في معاينة محلية داخل الصفحة. السجلات لا تستمر بعد مغادرة الصفحة ولا تُرسل إلى الخادم.
- لم يُنقل اتصال Supabase القديم ولا مفتاحه ولا الاعتماد على `localStorage.currentUser` لإثبات الهوية.
- لا توجد مصادقة أو API أو حفظ دائم أو بث مباشر أو مشاركة WhatsApp فعالة في هذه الشاشة.
- إحصائيات تقارير المحطة تظهر كغير متاحة، ولا يتم اختلاق أرقام أو بيانات مستخدم ومحطة.
- إحصاء «ظواهري النشطة» لا يعرض رقماً قبل تفعيل هوية المستخدم.
- يلزم اعتماد جدول `weather_phenomena` في قاعدة METRA الجديدة، وعقود API، وصلاحيات المحطة، والمنطقة الزمنية، ثم اختبار بدء/إنهاء السجل الحقيقي والبث المباشر ومشاركة WhatsApp.
