## 5. وظائف قديمة غير ممثلة كصفحات مستقلة في الجرد الحالي

يجب إضافتها إلى جرد المتطلبات قبل اعتبار حصر الشاشات مكتملاً:

1. **بلاغات مشاكل البرنامج والبيانات (IT):** شاشة تقديم بلاغ، اختيار النشرة والحقل، عرض رمز الحقل، تفاصيل المشكلة الديناميكية، متابعة البلاغات السابقة، حالات وأولويات.
2. **استعراض الظواهر التاريخية:** بحث حسب التاريخ والنوع والمحطة والشدة والفترة، عرض التفاصيل، جدول المطر/الثلج حسب الساعة UTC، وتصدير.
3. **لوحات التقارير المتخصصة:** فصل استعلامات الساعي واليومي والمناخي والمطري والزراعي والتربة بدلاً من افتراض أن مركز تقارير واحد يغطي كل اختلافاتها.
4. **لوحة رئيس الشبكات الشاملة:** النشرات الناقصة، أعطال المعدات، أعطال الاتصالات، مشاكل IT، التذكيرات، سجل النشاط، رسائل المستخدمين، التسجيل، الإحصاءات، النسخ الاحتياطية وSMS.
5. **إدارة دورة عطل الجهاز:** الإسناد إلى فني، تحديث نسبة الإنجاز، موعد الإصلاح، المرفقات، العاجلية، المتابعة، وإغلاق موثق.
6. **إدارة بلاغ الاتصالات:** تحرير البلاغ وتغيير حالته ومراجعة التفاصيل ومؤشرات الحالة والجهاز والشهر والمستخدم.
7. **التذكيرات والمراسلات:** إعداد الجدولة والتكرار وقوالب الرسائل وحالة الإرسال وسجل الرسائل، مع إعادة تصميمها بأمان وعدم نقل تكاملات المتصفح القديمة كما هي.

المقارنة الوظيفية لا تعني نسخ طريقة التنفيذ القديمة. يجب إعادة بناء السلوك ضمن معمارية 2027:

- كل مستخدم عادي محصور بمحطته؛ الوصول الشامل لرئيس دائرة الشبكات والمدققين المخولين فقط وفق سياسة الخادم واختبارات التفويض.
- لا اتصال مباشر من Flutter إلى جداول التشغيل، ولا مفاتيح service-role في العميل.
- لا استخدام قاعدة البيانات القديمة أو تنفيذ SQL عليها أو ترحيل بيانات منها دون موافقة مستقلة صريحة.
- لا تغيير مخطط Supabase الجديد أو نشر migrations قبل مراجعة واعتماد المستخدم.
- لا تعتمد القيم العلمية أو الرموز أو حدود التحقق قبل مراجعة قاموس البيانات والمراجع العلمية المعتمدة.
- لا تُنقل مفاتيح أو إعدادات أو بيانات اعتماد موجودة في ملفات المصدر القديم إلى التطبيق الجديد.
