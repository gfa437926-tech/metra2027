# السجلات المصورة والرقمنة ومقارنة الحقيقة المرجعية

## 1. الهدف والنطاق
إدارة دورة حياة صور السجلات الورقية والمسجلات الميكانيكية، مراجعة OCR/استخراج المنحنيات، وتصحيح النتائج ومقارنتها بالقيم المرجعية المعتمدة.

## 2. المستخدمون والصلاحيات
- الدور الأساسي: فني الرقمنة/المدقق/المختص العلمي بحسب التفويض.
- يجب تحميل صلاحيات المستخدم من سياق موثوق صادر عن الخادم.
- نطاق المحطة: المستخدم العادي يرى المحطة المخصصة له فقط.
- أي استثناء متعدد المحطات يجب أن يكون مفوضاً على الخادم، لا مستنتجاً من دور الواجهة.
- لا تعرض أزرار تعديل/اعتماد/حذف إلا إذا كانت العملية مسموحة من الخادم.

## 3. الشاشة وتجربة الاستخدام
أرشيف؛ رفع/التقاط صورة؛ بيانات وصفية؛ معاينة أصلية؛ أدوات معايرة؛ نتائج OCR/منحنى؛ تصحيح بشري؛ مقارنة ثلاثية (ورقي/ميكانيكي/إلكتروني)؛ مقارنة مع ground truth؛ اعتماد.

المتطلبات المشتركة:
- واجهة عربية RTL، عناوين واضحة، تسلسل بصري ثابت، ودعم الهاتف واللوحي وسطح المكتب.
- حالات تحميل، فارغ، خطأ، انقطاع اتصال، منع صلاحية، ونجاح.
- لا تكرر القائمة الجانبية؛ استخدم مكون التنقل المشترك.
- حافظ على قيم النموذج عند أخطاء الشبكة ما لم يطلب المستخدم إعادة الضبط.
- وضّح المنطقة الزمنية ووحدة القياس عند عرض الوقت أو القيم العلمية.

## 4. الحقول والبيانات
المحطة والجهاز ونوع المسجل وفترة الالتقاط والمنطقة الزمنية ونوع المخطط والصورة الأصلية ونسخة العرض والمعايرة والمرشح والثقة والقيمة المرجعية والفروقات؛ وفق contracts.

**قاعدة التوثيق:** الحقول أعلاه تصف مجموعات البيانات المطلوبة، ولا تعتبر قائمة أسماء نهائية. يجب استخراج أسماء الحقول وأنواعها وحدودها من النموذج الأصلي وملفات mapping والعقد العلمي المعتمد. لا تخترع حدوداً أو وحدات أو قيم تعداد.

## 5. سير العمل
إنشاء طلب التقاط ← حجر وفحص الملف ← إدخال metadata ← بدء مهمة رقمنة عبر API ← مراجعة المرشح ← مقارنة المرجع ← تصحيح/اعتماد مع provenance.

## 6. الإجراءات
طلب التقاط؛ متابعة مهمة؛ عرض صورة؛ تصحيح؛ مقارنة؛ اعتماد/رفض وفق API.

## 7. الربط والخدمات
- ملف/ملفات Flutter المرشحة: `features/records/records_review_workspace_screen.dart`, `record_capture_request.dart`, `record_digitization_job_status.dart`, `record_image_asset_status.dart`; contracts في docs/architecture.
- طبقة الاتصال: `core/api/metra_api_client.dart` وعقود .NET المعتمدة فقط.
- لا اتصال مباشر من Flutter إلى جداول PostgreSQL.
- حالة API: يجب التحقق من المسارات الفعلية والعقود المنشورة قبل وصف الربط بأنه مكتمل.
الكتالوج يصف metadata والدرافت المحلي؛ OCR/curve extraction والتخزين الآمن والحجر والمسح لا تعتبر متاحة قبل نشر خدماتها.

## 8. التحقق والاختبارات
اختبارات MIME والحجم والحجر والفيروسات والصلاحيات وسلامة الأصل وسلسلة المصدر والوحدات والتفاوتات.

## 9. سجل التدقيق والخصوصية
- سجّل الفاعل والوقت ومعرف السجل والإجراء والنتيجة وسبب الرفض/الإرجاع عند توفرها في عقد الخادم.
- لا تسجل كلمات المرور أو الرموز السرية أو محتوى حساساً غير لازم.
- لا تعرض بيانات محطة خارج نطاق صلاحية المستخدم.

## 10. الحالة والاعتماد
- حالة المواصفة: أُنشئت / تحتاج مطابقة مصدرية واعتماد مالك المجال.
- حالة التنفيذ: لا تُعد مكتملة بناءً على وجود هذه الوثيقة.
- شروط الإغلاق: مطابقة النموذج المصدر، اعتماد الحقول والقواعد، تنفيذ الواجهة، ربط API، اختبارات ناجحة، مراجعة RTL والاستجابة.
