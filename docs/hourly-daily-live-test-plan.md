# خطة اختبار حي — hourly / daily

تاريخ: 2026-11-16  
الفرع المرجعي: `feat/phenomenon-observation-submit-2026-11-16`  
الحالة: **خطة فقط** — لا migrations ولا تغيير RPC ولا تعديل schema في هذه الوثيقة.

## الهدف

إثبات على بيئة حقيقية (Staging مع بيانات معتمدة) أن:

1. حفظ hourly وdaily يعمل عبر المسار المعتمد.
2. Idempotency يمنع التكرار الفعلي عند إعادة نفس المفتاح.
3. عزل المحطات يمنع الوصول عبر المحطات.
4. الصلاحيات تُرفض للمستخدم غير المصرح.

## المتطلبات المسبقة (بدون تغيير DB هنا)

| البند | ملاحظة |
|---|---|
| `METRA_API_BASE_URL` | HTTPS staging |
| حسابان مستخدمان | A مكلف بمحطة S1؛ B بمحطة S2 أو بلا تكليف |
| JWT صالح | من Supabase Auth staging |
| صلاحية `observation.create` | على S1 للمستخدم A فقط |
| RPC `metra_submit_observation` | كما هو منشور — **لا تعديل** في هذه الخطة |

أي فجوة في RPC أو RLS تُوثَّق كتقرير عيب وتُعرض للموافقة قبل أي migration.

## حالات الاختبار

### L1 — إرسال ساعي صالح

- فاعل: المستخدم A، المحطة S1.
- خطوات: تعبئة حقول hourly الدنيا المعتمدة → validate → submit بمفتاح `live-hourly-<uuid>`.
- متوقع: HTTP 2xx؛ وجود سجل واحد فقط لنفس المفتاح.

### L2 — إعادة نفس مفتاح hourly (idempotency)

- نفس جسم L1 ونفس `idempotencyKey`.
- متوقع: لا سجل مكرر؛ استجابة نجاح أو 409 متسقة مع عقد RPC الحالي.
- يُسجَّل السلوك الفعلي (200 مكرر / 409) كما هو دون افتراض.

### L3 — حمولة متعارضة بنفس المفتاح

- نفس المفتاح مع تغيير حقل واحد (مثل `dryTemp`).
- متوقع: رفض أو تعارض صريح؛ لا صامتة الكتابة فوق بيانات مختلفة دون سياسة معتمدة.

### L4 — إرسال يومي صالح + إعادة المفتاح

- مثل L1/L2 لنوع `daily`.

### L5 — عزل المحطة

- المستخدم A يحاول `POST /stations/{S2}/observations`.
- متوقع: 403؛ لا استدعاء نجاح للحفظ.

### L6 — مستخدم بلا صلاحية

- المستخدم B على S1.
- متوقع: 403.

### L7 — انقطاع وإعادة محاولة من العميل

- إرسال ينقطع بعد قبول الخادم (محاكاة شبكة).
- العميل يعيد بنفس المفتاح.
- متوقع: لا تكرار منطقي في البيانات.

## ما لا يُنفَّذ في هذه الخطة

- لا إنشاء جداول أو سياسات RLS جديدة.
- لا تعديل `metra_submit_observation`.
- لا استخدام قاعدة `metra-old`.
- لا ربط نماذج غير معتمدة (زراعي، مطر، …).

## مخرجات التنفيذ اللاحق

- سجل نتائج لكل حالة (PASS/FAIL + رمز HTTP + معرّف الرصد إن وُجد).
- قائمة عيوب تتطلب موافقة schema/RPC إن ظهرت.
- توصية Go/No-Go للإنتاج لمسار hourly/daily فقط.
