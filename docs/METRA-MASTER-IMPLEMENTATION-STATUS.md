## 2. مقارنة المصادقة (تفصيلية)

### 2.1 PR #54 (`metra2027` / `metra_auth.dart`)
- **نقاط القوة:**
  - `MetraSecureSessionStorage` باستخدام `flutter_secure_storage`.
  - Configuration gate واضح (لا تشغيل بدون METRA_API_BASE_URL + Supabase publishable).
  - رسائل خطأ عربية آمنة (لا تسريب تفاصيل داخلية).
  - استعادة كلمة المرور عبر `resetPasswordForEmail`.
  - لا يسمح بإنشاء حسابات من التطبيق (نص صريح: اطلب تفعيل الحساب من المسؤول).
  - ربط مباشر بـ `MetraApiClient` عبر access token من الجلسة.
- **نقاط الضعف:**
  - لا يوجد مسار تسجيل طلب انتساب كامل داخل هذا الفرع.
  - لا يوجد فحص `account_state` (pending / rejected / suspended) بعد تسجيل الدخول.
  - لا يوجد ربط صريح للمستخدم بمحطته وصلاحياته بعد الدخول (يُفترض أن API يفرضه).

### 2.2 المستودع المستقل (`metra-weather-intelligence2026`)
- **نقاط القوة:**
  - `RegistrationGate` كامل: يفحص `account_state` عبر Edge Function.
  - حالات: `active` / `needs_registration` / `pending*` / مرفوض.
  - نموذج تسجيل طلب انتساب (الاسم، الأب، العائلة، الهاتف، الدور، المحطة، الشروط).
  - idempotency_key + تحقق من أهلية المحطة (معتمدة + تشغيلية).
  - رسائل عربية واضحة لكل حالة.
- **نقاط الضعف:**
  - يعتمد على Edge Functions (ليس .NET API).
  - الجلسة تعتمد على Supabase client العادي (بدون secure storage مخصص بنفس القوة).
  - لا يوجد تكامل مباشر مع `MetraApiClient` الخاص بـ .NET.

### 2.3 القرار المعتمد
| الوظيفة | المصدر المعتمد | ملاحظات |
|---------|----------------|---------|
| تسجيل الدخول + الجلسة الآمنة | PR #54 | secure storage + configuration gate |
| استعادة كلمة المرور | PR #54 | موجود |
| فحص حالة الحساب بعد الدخول | المستودع المستقل (منطق) | يجب نقله إلى .NET أو توحيده |
| طلب الانتساب + الموافقة | المستودع المستقل (منطق + Edge) | مرجع تصميم؛ الهدف النهائي عبر .NET API |
| ربط المستخدم بالمحطة والصلاحيات | Backend .NET | يجب أن يكون المصدر الوحيد للحقيقة |

**لا ازدواجية:** نحتفظ بهيكل PR #54 كأساس، ونضيف منطق حالات الحساب وطلب الانتساب لاحقاً عبر عقود .NET.

## 5. الأعمال المنجزة vs المتبقية (أولوية عالية)

### منجز فعلياً
- كتالوج 174 حقلاً مربوط في Flutter.
- نموذج إدخال موحد RTL مع validation.
- مسار hourly/daily: validate + submit + idempotency.
- دليل محطات + قائمة مراجعة + قرارات أساسية.
- Configuration gate + secure session storage.
- CI (analyze + tests + web build) على PR #54.

### متبقي عالي الأولوية (آمن للتنفيذ الآن)
1. توحيد معالجة الوقت (UTC vs local) في النماذج والـ payload.
2. تحسين رسائل الأخطاء العربية في مسارات الاتصال وانتهاء الجلسة.
3. معالجة انقطاع الإنترنت وفشل الشبكة بشكل موحد.
4. تحسين التحقق قبل الإرسال (منع NaN/Infinity بشكل أقوى إن لزم).
5. إضافة/تقوية اختبارات للـ 174 حقلاً وللحالات الحدية.
6. توثيق حالة كل شاشة في الواجهة (service notice موجود جزئياً).

### متبقي يتطلب موافقة أو عمل أكبر
- API حفظ للنماذج السبعة المتبقية.
- نظام RBAC كامل + اختبارات IDOR.
- وحدات CLIMATOL / OCR / AI / مقارنة / أجهزة / تقارير.
- أي migration أو تغيير في Supabase.
