## 2. ما لن يُعلن جاهزاً للإنتاج قبل إجراءات المالك

1. تطبيق migrations على مشروع Supabase **الجديد** فقط (موافقة مرحلة E).  
2. أسرار التشغيل في مخزن أسرار البيئة (ليس في Git وليس في Angular/Flutter):
   - `Supabase:Url` / مفاتيح عامة للعميل فقط في إعدادات العميل  
   - مفتاح **service role** خادمي فقط  
   - `ConnectionStrings:MetraOps` إن فُعّل مسار Npgsql  
   - إعدادات JWT / JWKS  
3. بيئة Staging منفصلة + تجربة حسابات حقيقية متعددة المحطات.  
4. نسخة احتياطية / استعادة مختبرة.  
5. HTTPS وترويسات أمن على المنشور.  
6. دمج PR #11 إلى `main` بعد مراجعتك.  
7. نشر Backend + Angular + تجهيز حزمة Flutter للمتاجر/التوزيع الداخلي.

## 3. قائمة تحقق قبول تجريبي (Staging)

| # | السيناريو | نتيجة متوقعة |
|---|---|---|
| 1 | دخول بمستخدم محطة A | يرى فقط نطاق A |
| 2 | محاولة API لمحطة B | 403 |
| 3 | إدخال نشرة ساعية/يومية | إيصال حفظ + id من الخادم |
| 4 | مراجعة من مستخدم مخوّل غير الراصد | اعتماد/إرجاع يعمل |
| 5 | محاولة اعتماد ذاتي إن وُجدت قاعدة SoD | رفض |
| 6 | إرجاع بملاحظة → تصحيح → إعادة تقديم | يعود للطابور |
| 7 | بلاغ عطل / حادث دعم | دورة ضمن المحطة |
| 8 | تأكيد أرشفة Excel | سجل إداري؛ لا ترحيل أرصاد |
| 9 | انقطاع خدمة الصلاحيات | فشل مغلق (لا سماح) |
| 10 | عملاء بلا service role في الحزم | فحص ثابت |

## 4. إعداد الأسرار (إرشاد فقط — لا تُرسل أسراراً في الدردشة)

| السر | أين يوضع | أين لا يوضع |
|---|---|---|
| `anon` / publishable | إعدادات Angular/Flutter العامة | Git إن كان خاصاً ببيئة |
| `service_role` | خادم .NET / Secret Store فقط | Angular · Flutter · المستودع |
| DB URL / MetraOps | Secret Store للخادم | أي عميل |
| JWT HS256 إن وُجد | خادم فقط أثناء الانتقال | العملاء |

الجلب النموذجي: لوحة Supabase → Project Settings → API / Database؛ ثم GitHub Actions secrets أو Azure Key Vault / معادلها.
