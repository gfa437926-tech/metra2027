# METRA 2027

METRA 2027 is maintained as three independently runnable applications:

| Application | Technology | Folder | Default local address |
|---|---|---|---|
| Web | Angular 20 | `angular-app/` | http://localhost:4200 |
| Mobile | Flutter | `mobile/metra_mobile/` | Android / iOS device or emulator |
| Backend API | ASP.NET Core 10 / C# | `backend/Metra.Api/` | https://localhost:7001 |

## Independent operation

Each application has its own project files, dependencies, startup command, and development lifecycle. You can work on or run any one of them without starting the other two.

The web and mobile clients will share the ASP.NET Core API when integration is implemented. The API is a separate service; neither client hosts or embeds the backend. Until API integration is enabled, the clients can launch independently in their own UI scaffold mode.

## Run only the web application

Requirements: Node.js (LTS) and npm.

```bash
cd angular-app
npm install
npm start
```

Open http://localhost:4200. Production build: `npm run build`.

## Run only the mobile application

Requirements: Flutter stable SDK, Android Studio / Android SDK for Android, and Xcode on macOS for iOS.

Generate the native platform runner folders once (they are intentionally generated by Flutter tooling rather than hand-maintained):

```bash
cd mobile/metra_mobile
flutter create --platforms=android,ios .
flutter pub get
flutter run
```

On Windows or Linux, generate Android only with `flutter create --platforms=android .`. iOS builds require macOS and Xcode.

## Run only the backend API

Requirements: .NET 10 SDK.

```bash
cd backend/Metra.Api
dotnet restore
dotnet run
```

Check the service at `/api/v1/health`. OpenAPI is available in Development at `/openapi/v1.json`.

## Configuration and data

- Configure API CORS origins in `backend/Metra.Api/appsettings.Development.json` or environment variables.
- Flutter API URL can be supplied at launch with `--dart-define=METRA_API_BASE_URL=https://your-api-host` when API calls are introduced.
- Do not commit credentials, signing keys, database passwords, or production secrets.
- No database schema, Supabase project, or access policies are modified by this project scaffold.

## Current scope

This repository contains independent application entry points and starter interfaces. Full climate-record workflows, authentication, API integration, and persistence are subsequent implementation tasks and are not represented as completed.
